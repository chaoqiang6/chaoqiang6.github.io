先不急着做 Agent

第一次接触 LangChain 时很容易直接研究 Agent，结果把模型、工具、记忆和执行器混在一起。实际项目可以先从一个普通的 prompt chain 开始，确认模型调用、输入输出和异常处理。

Runnable 的组合方式比较直观。prompt 负责组织输入，model 负责调用模型，parser 负责把结果转换成应用可以使用的格式。每个环节都可以单独替换和测试。

为什么要控制输出

让模型只返回一段自然语言，后端很难稳定处理。可以使用结构化输出，让模型返回符合 schema 的对象，但仍然要在服务端做校验，模型输出不能直接当成可信数据执行。

目前我的感觉是，LangChain 最大的价值不在于少写几行调用代码，而在于把 prompt、模型、解析器和运行追踪拆成可以组合的组件。项目变复杂以后，依赖版本和抽象层变化也要重点关注。
