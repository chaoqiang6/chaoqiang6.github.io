大模型接口为什么突然变慢

一次问答请求的耗时不只有模型生成时间，还可能包括向量检索、工具调用、重试和上下文拼接。如果只记录 Controller 的总耗时，就看不出到底是哪一步慢。

应该为检索、模型调用和工具调用分别记录 span，并把 traceId 传递下去。模型输入和输出 token 数也要记录，但原始 prompt 可能含有密码、手机号等敏感信息，日志需要脱敏或只保存统计值。

成本和延迟一起看

输入 token 太多会增加费用和首字节延迟，输出 token 太多会拉长整体响应。可以限制历史消息长度、压缩 RAG 上下文、设置 max tokens，并对不同业务选择不同模型。

指标至少包括成功率、超时率、p50/p95 延迟、输入输出 token、工具调用失败数和模型错误码。AI 接口也应该像普通 RPC 一样有超时、重试上限、熔断和降级。

最近补这一块时最大的感受是，接入模型本身并不难，难的是把它放进已有的可靠性和成本管理体系里。
