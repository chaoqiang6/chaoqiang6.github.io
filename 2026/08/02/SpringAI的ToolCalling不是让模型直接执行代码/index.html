工具调用的真实流程

用户问“帮我查一下订单”，模型并不会真的访问数据库。它先根据工具描述生成一个工具调用请求，应用收到请求后决定是否执行，再把结果返回给模型组织答案。

这里的 Function 仍然运行在我们的 Java 进程里，权限、参数校验、审计和超时都应该由应用负责。不能因为调用是模型发起的，就把普通接口的安全检查去掉。

哪些工具需要人工确认

查询天气可以自动执行，取消订单、转账、删除数据就不应该只凭模型的一句话直接执行。可以把工具分成只读和有副作用两类，后者要求用户二次确认，或者进入审批流程。

模型生成的参数要当成不可信输入，尤其要防止越权查询和 prompt injection。工具描述写得越清楚，模型越容易正确选择，但清晰描述不能代替服务端校验。

这部分和传统后端很像：模型只是一个不稳定的调用方，真正的业务边界仍然要落在服务端。
