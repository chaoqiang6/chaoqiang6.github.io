分布式ID为什么不用数据库自增

自增 ID 的局限

单库自增简单，但多节点写入时容易冲突；把所有请求集中到一个发号表，又会增加中心节点压力。ID 还可能暴露业务规模。

常见方案

Snowflake 组合时间、机器号和序列号，通常趋势递增；UUID 冲突概率很低，但随机性会让 B+Tree 索引写入不够友好；数据库号段模式可以批量申请一段 ID，减少访问次数。

Snowflake 需要处理时钟回拨，机器标识也必须保证唯一。方案的可用性边界比 ID 本身的格式更重要。

结论

选择分布式 ID 要看排序、长度、可读性、离线生成和时钟可靠性，不能只比较“会不会重复”。
