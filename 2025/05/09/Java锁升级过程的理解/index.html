synchronized 不是永远重量级

HotSpot 会根据竞争情况优化锁的获取。无竞争时路径很轻，竞争增加后可能进入更重的同步机制。不同 JDK 版本实现细节会变化，不能把旧资料中的偏向锁流程当成永远不变的规范。

真正影响性能的通常是临界区大小、竞争程度和线程调度，而不是关键字本身。

如何验证

用 JMH 对比有竞争和无竞争场景，观察吞吐和 p99，不要用一个简单 main 方法得出结论。业务代码还要确认锁对象是否稳定，避免锁住字符串常量或暴露对象。

结论

锁优化应该建立在基准测试上。缩小临界区、减少共享状态，通常比纠结某个内部锁标志更有效。
