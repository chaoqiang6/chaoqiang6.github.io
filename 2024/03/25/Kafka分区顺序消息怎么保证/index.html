Kafka分区顺序消息怎么保证

顺序的范围

Kafka 只能保证同一个 partition 内的消息有序，不能保证整个 topic 的全局顺序。生产者需要把同一业务键发送到同一个分区。

默认分区器会根据 key 选择分区。业务 key 改变后，相关事件可能被分散到不同分区，顺序自然无法保持。

消费端也会破坏顺序

同一个 partition 在同一消费组内只会被一个消费者消费，但消费者内部如果把消息提交到异步线程池，完成顺序仍可能反过来。需要限制并发，或者按 key 做串行队列。

先问业务一个问题

需要的是同一订单有序，还是所有订单全局有序？这个答案会直接影响 partition key 和消费并发。
