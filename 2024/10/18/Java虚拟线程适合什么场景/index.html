虚拟线程解决什么

传统线程通常一对一映射到操作系统线程，阻塞 IO 时也占着线程资源。虚拟线程由 JVM 调度，适合大量等待网络或文件 IO 的任务。

代码仍然可以写成同步风格，但不代表下游数据库和 HTTP 服务的容量自动变大。

需要注意

CPU 密集型任务不会因为换成虚拟线程就变快。长时间持有 synchronized、调用不支持挂起的 native 方法，也可能造成载体线程被阻塞。连接池和限流仍然需要设置。

结论

虚拟线程降低的是大量阻塞任务的线程成本，不是所有并发问题的解决方案。上线前要用真实 IO 模型和下游容量压测。
