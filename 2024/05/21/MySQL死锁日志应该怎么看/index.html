MySQL死锁日志应该怎么看

  • MySQL 
  • | InnoDB 

先拿到现场

重点看 LATEST DETECTED DEADLOCK，里面会列出两个事务持有的锁和正在等待的锁。

一个典型顺序

事务 A 先更新 id=1，再更新 id=2；事务 B 先更新 id=2，再更新 id=1。两个事务互相等待，就形成环路。

死锁不等于数据库坏了，InnoDB 会主动回滚其中一个事务。应用应该捕获死锁异常并在有限次数内重试，同时从业务上统一加锁顺序。

处理顺序

先保留死锁现场，再统一访问顺序、缩短事务范围和检查索引。单纯调大锁等待时间通常只是延迟问题。
